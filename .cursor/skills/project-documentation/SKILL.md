# 项目文档

## 何时启用

用户要**新增或修订**下列任一类文档时，按对应章节执行；若未指定类型，先问清受众（开发者 / 终端用户 / 论文读者）与交付物路径，再动笔。

## 通用原则

- **以代码与配置为准**：安装命令、CLI 参数、环境变量、默认路径必须与仓库实际一致；不确定时先读 `pyproject.toml` / `setup.cfg` / `environment.yml` / 入口脚本再写。
- **单一事实来源**：安装与运行步骤优先引用仓库已有脚本或 CI 中的命令，避免在多处复制粘贴导致漂移。
- **可执行性**：README 中的命令应在当前仓库根目录可复制运行（注明 OS/shell 差异时用注释或分节说明）。
- **渐进披露**：README 保持短而可上手；细节放到 API 文档、用户手册或 `docs/` 子页，并在 README 中链接。

## 1. README（含安装与项目说明）

**目标**：新克隆仓库的人能在合理时间内跑通最小路径，并理解项目是什么、不是什么。

建议结构（按需取舍，不必照抄标题）：

1. **一句话说明** + 可选徽章（license、CI）。
2. **功能与范围**：解决什么问题、适用场景与已知限制。
3. **环境要求**：语言/运行时版本、GPU、操作系统说明。
4. **安装**：从源码安装、conda/pip、可选的「最小依赖」与「开发依赖」分节。
5. **快速开始**：一条最短可复现命令链（数据若大，说明如何用小样例或 `--help` 自检）。
6. **项目结构**：顶层目录职责（一两段 + 可选树状列表）。
7. **文档索引**：指向 API 文档、用户手册、测试说明的链接。
8. **引用与许可**：论文 BibTeX、许可证文件名。

验收：按 README 从空环境走到「快速开始」成功，且无与代码矛盾的参数名。

## 2. API 文档

**目标**：维护者可依赖其理解**公共 API**（模块边界、函数签名、返回值、异常与副作用），而不必读遍实现。

做法：

- **范围**：仅对「有意对外暴露」的符号写文档（包 `__all__`、CLI、插件接口）；内部实现用简短模块 docstring 即可。
- **形式**：优先与语言生态一致（Python 用 Sphinx/MkDoc 风格 docstring；TypeScript 用 TSDoc）。若仓库无站点生成器，至少在源码 docstring 中写清参数、形状/单位、Raises。
- **契约**：写清 I/O 类型、张量形状约定、线程/GPU 行为、破坏性变更时如何迁移。
- **示例**：每个复杂公共函数旁给一个最小调用示例（可来自真实测试用例的精简版）。

验收：公共 API 在 IDE 悬停或生成的 HTML 中可读，且示例可运行或与测试一致。

## 3. 用户手册

**目标**：**非开发者**或**运维/标注人员**能按任务完成操作（训练、推理、导出、排障）。

建议包含：

- **角色与前置条件**（账号、数据格式、磁盘空间）。
- **按任务分章**：例如「准备数据」「训练」「评估」「部署」；每章有前置检查与预期产出。
- **界面说明**：若有 GUI/CLI，列出子命令、配置文件字段表、常见错误码。
- **故障排除**：症状 → 原因 → 解决步骤；指向日志关键字与相关 Issue/FAQ。

语气：步骤编号清晰，少用内部类名；必要时配图或录屏说明放在 `docs/images` 并在文中引用。

## 4. 测试文档

**目标**：贡献者知道如何跑测试、写哪类测试、CI 期望。

建议包含：

- **如何运行**：`pytest` / `npm test` 等完整命令；如何只跑单元/集成/慢测（若项目已分标记）。
- **环境**：与 README 的差异（如额外服务、fixture 数据下载方式）。
- **约定**：目录布局、fixture 命名、mock 外部依赖的规则。
- **覆盖率或门禁**：若 CI 有阈值，写明并链接配置。

验收：新贡献者按文档可在本地复现 CI 同套测试命令（或文档明确说明与 CI 的差异及原因）。

## 5. 其他常见类型（按需）

| 类型 | 要点 |
|------|------|
| **CHANGELOG** | 版本号、日期、Breaking / Added / Fixed；与 tag 或发布流程一致。 |
| **CONTRIBUTING** | 分支策略、PR 检查清单、代码风格命令、如何更新上述文档。 |
| **安全 / 隐私** | 报告渠道、数据脱敏要求、默认不记录敏感信息。 |

## 反模式

- 文档中的命令从未在仓库或 CI 中验证过。
- 复制大段过时教程，与当前默认配置冲突。
- 只写「详见代码」而无对外可读的签名与行为说明（API 文档场景）。
- 用户手册充斥实现细节却无「我要完成 X 怎么做」的路径。

## 与本仓库协作

撰写或修改文档前，快速浏览现有 `README.md` 与 `src/` 包入口，避免重复或矛盾的安装路径；若项目增加新 CLI 或配置键，**同步更新** README 与相关手册章节。
